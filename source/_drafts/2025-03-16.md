## 什么是 Registry？为什么我们需要它？

目前我们在使用 Swift Package 的时候，指向的依赖通常都是一个 Git 仓库，例如：

```swift
dependencies: [
    .package(url: "https://github.com/Alamofire/Alamofire.git", from: "5.10.0")
]
``` 

这是最自然的一种方式，因为我们在写代码的时候基本上都在使用 Git 来管理代码，但对于 Package Manager 来说，它存在一些问题。

Package Manager 需要知道一个 Package 的：

- Package.swift 文件（在 Version Resolve 的过程中）
- 代码/二进制包（在编译的过程中）

Package Manager 并不关心依赖库的版本历史 commit 记录，它只关心特定版本的内容。

它需要在 Version Resolve 的过程中，快速“遍历”不同版本的依赖库，以便找到一个最合适的版本。

但 Git 的局限性在于，它并不能很好地满足这个需求。

例如说 Firebase 和 AWS 的 SDK 这种大型仓库，fetch 和 checkout 的时间会非常长，这会导致 Version Resolve 的过程非常慢。

https://github.com/swiftlang/swift-package-manager/issues/5545

### 什么是 Registry

Registry 是一个集中化的存储库，它提供了接口可以快速查询：

- 特定库的所有版本
- 特定库的 Package.swift 文件
- 特定库的代码/二进制包

在 Package resolve 的过程中，Package Manager 可以直接从 Registry 中获取到特定版本的内容，而不需要从 Git 中 clone 整个仓库。

这对于大型仓库来说，可以大大减少 resolve 的时间。

## Swift Registry

### 实现

Swift Registry 的协议并不复杂，满打满算就 7 个接口：

- `GET /{scope}/{name}`：获取指定 Package 的所有版本
- `GET /{scope}/{name}/{version}`：获取指定 Package 指定版本的 Metadata
- `GET /{scope}/{name}/{version}/Package.swift`：获取指定 Package 指定版本的 Package.swift 文件
- `GET /{scope}/{name}/{version}.zip`：获取指定 Package 指定版本的代码
- `GET /identifiers`：获取所有 Package 的 id
- `PUT /{scope}/{name}/{version}`：上传指定 Package 的指定版本
- `POST /login`：登录

并且这几个接口不是强制要求实现的，只有前面 4 个接口是强制要求实现的，后面 3 个接口是可选的，至少.
